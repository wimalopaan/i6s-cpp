# i6s-cpp

C++26 port of the FlySky FS-i6X firmware (originally `ferrox-rc/flysky-i6x-rs`, Rust).

Constraints: CMSIS only (no HAL), `constexpr`/`consteval` where possible, static polymorphism only (no virtual), no heap, no exceptions/RTTI.

## Status: foundation, CRSF, storage, mixer, input, RC output, LCD, dashboard, menus, main-menu diagnostics, calibration, dual rate/expo, throttle curve, wing/mixer, telemetry tile logic

Ported so far:
- Chip/CMSIS: system clock (48 MHz), reset flags, DFU entry and jump, UID
- Independent watchdog
- SysTick millisecond timer
- GPIO helpers, ADC scan (DMA), USART2 with BRR logic, keys matrix and DFU check
- Pure constexpr logic (BRR, battery voltage, key bits, SPSC ring) with host tests
- CRSF: CRC-8, channel scaling and RC frame (16 ch, optional ELRS arm flag), byte framer, telemetry parser (link stats, battery, vario, baro, cells, GPS, RPM, temp, attitude, flight mode), 100 Hz TX pacing, 1 s telemetry timeout. Logic in `logic/crsf.hpp` (host-tested), USART/power glue in `hw/crsf.hpp`. Wired into `main.cpp` (telemetry and menu polling; RC output off until mixer exists). Not tested on hardware.

- CRSF parameter menu (API only, no LCD UI): device discovery via ping and device info, parameter loading in folder order with chunks, retries and timeouts, value write (clamped, select cycling), folder navigation, and command state machine. Engine in `logic/crsf_menu.hpp` (host-tested, Loader ~4.8 KB RAM), glue in `hw/crsf.hpp`. Not tested on hardware.

- Storage: external I2C EEPROM driver (I2C2, PB10/PB11, probes 0x50..0x57), A/B radio slots with CRC-16 and fallback, model slots, sanitize rules, and legacy v1–v4 migration. Logic in `logic/storage.hpp` (host-tested, layout checked with static_asserts), driver in `hw/eeprom.hpp`. Loaded at boot in `main.cpp`. Saves are not yet triggered from a UI. Not tested on hardware.

- Mixer (pure logic, host-tested): channel constants, switch model, trim offsets (`logic/trim.hpp`), and the full channel pipeline with 32 matrix lines, wing/tail templates, dual rates and expo, dynamic weights from pots/GVars, heli/arm lockout, timers, and channel reversing (`logic/mixer.hpp`). Not yet wired into the RC output because the arm/safety/idle logic is not ported. Not tested on hardware.

- Input (pure logic, host-tested): stick and pot filtering and normalization with detent and Hall deadbands, ADC mode resolution, 2/3/6-position switch decoding, SE/SF pin decoding, extended ADC switches, and battery EMA filter (`logic/input.hpp`). Calibration comes from the radio storage. Wired into `main.cpp` (PC12/PC15 read as board switches). Not tested on hardware.

- RC output (pure logic, host-tested): startup preflight (throttle position per model type, heli throttle hold, safe switches, cancel key), safe-idle failsafe pulses, stick mode mapping, and the mixer call for RC channels with arm lockout (`logic/safety.hpp`, `logic/flight.hpp`). Wired into `main.cpp`: preflight runs at boot unless the watchdog reset, CRSF uses the model baud rate, and channels are sent when `rf_protocol == 1`. Not tested on hardware.
- LCD (ST7567 128x64, 6800-style bus on GPIOE data bus): CMSIS-only driver with init, backlight PWM (TIM3 CH4) and page flush (`hw/st7567.hpp`). Framebuffer primitives, 4x6 and 6x10 fonts (verified byte-for-byte against the Rust tables), and header, footer, list, gauge, progress and scrollbar widgets are constexpr and host-tested (`logic/framebuffer.hpp`, `logic/fonts.hpp`, `logic/widgets.hpp`). Glyphs, logo, and number formatting (`logic/glyphs.hpp`, `logic/format.hpp`) are host-tested. Pot and channel-gauge widgets are added to `logic/widgets.hpp`.
- Dashboard (pure logic, host-tested): status bar (model name, CRSF, AFHDS2A BIND, RSSI or RF:OK/NO RF, battery gauge with low-battery blink), page paging with keys (5 pages), gimbals page P1 (general and aircraft variants, default and adaptive switch/pot layout), channel monitor P2/P3, model page P4, AFHDS2A telemetry page P5 (RSSI, link, RX and TX voltage, stale after 2.5 s, bind footer), splash (`logic/dashboard.hpp`). `main.cpp` shows the splash for 1.2 s, then renders at 10 Hz. Not tested on hardware.

- Menus (pure logic, host-tested): hold OK for 1.2 s on the dashboard to open the menu. Main menu with 3-row scrolling list and the 12 Rust 12x12 icons, model select (20 models, names read from EEPROM on entry, OK loads a model and reconfigures CRSF), and model setup for name (char editing), type, arm switch and timer. Cancel saves and steps back. Dual rate/expo (main menu item 2): switch (only usable switches, SA..SF), axis (Roll/Pitch/Yaw), Hi/Lo rate and Hi/Lo expo per axis with the Rust clamp ranges. Saved on cancel. Throttle curve (main menu item 3): Pts cycles 5, 7, 9 with the Rust resampling, Crv toggles linear and Catmull-Rom spline, each point 0..100% is edited with Up/Down and OK moves to the next point. The curve is evaluated in `logic/curve.hpp` (constexpr, host-tested, same math as Rust `curve.rs`) and applied to the throttle channel in `logic/flight.hpp`. Saved on cancel and on each commit. Wing & Mixer (main menu item 4): wing template (Normal, Elevon/Delta, V-Tail, Flaperon) cycles on OK, Diff (±100%, shown only for Elevon and Flaperon), a GVars entry (GV1..GV5, ±1000 in steps of 50), and 32 mix lines. Each mix line edits target (CH1..CH18 or Disabled), source, weight source, weight and offset (±100%), switch condition and mode (ADD, MULT, REPL). Unusable sources, weight sources and switch conditions are skipped using the same rules as Rust `storage.rs`. Cancel in a mix line returns to its row without saving. The Wing screen saves on cancel. Logic in `logic/menu.hpp`, names in `logic/labels.hpp` (host-tested). Channel reverse (per-model bit toggle, saved on cancel), aux channels (main menu item 5: CH5..CH18 source per channel, Up/Down steps through the sources usable under the Rust `storage.rs` rules, saved on cancel from the list; the Rust pot/jog auto-assign is not ported), channel monitor (3 pages of 6 channels, wrapping), analog diagnostics (2 pages, raw ADC values), diagnostics pages 2–4 (external switches SE/SF, external ADC P7 with 4 channels, and EEPROM status: address, boot read and last write), and system info (MCU name, firmware version and git hash, flash, EEPROM storage status and profile count). Up/Down and OK wrap through the five diagnostics pages, and the pages are pure logic in `logic/menu.hpp`, host-tested. Deviations from Rust: the external switch and P7 pages use the radio's ext switch and ext ADC enable flags instead of the input calibration copy, the EEPROM bus is always I2C2 (so no "Unknown" branch), the EEPROM write error is the result of the most recent write, and system info shows the same five rows as Rust `update_system_info`: the Firmware row is `v0.27.0 (hash)`, with the version from the CMake project and the hash from `git rev-parse --short HEAD` at configure time (`unknown` without git). The Storage row is always I2C2. Rows are formatted by `logic/sysinfo.hpp` (host-tested). Key repeat after 300 ms, every 70 ms. Logic in `logic/menu.hpp`, shared labels in `logic/labels.hpp`, icon bitmaps in `logic/glyphs.hpp` (host-tested). Wired into `main.cpp`. Not tested on hardware.

- Calibration wizard (pure logic and rendering, host-tested): start from the main menu "Calibration" entry, which closes the menu. Steps: centre (OK captures), limits (move all sticks and configured pots, OK saves once every stick has enough travel), complete screen for 1.2 s. Stick endpoints get a 63/64 margin. Pots are saved only with at least 400 counts of travel. Pot centre and limits are kept in separate arrays from the sticks, which fixes a Rust bug where pot channels 0–3 overwrote the stick endpoints. Saved to EEPROM with `save_radio_config`. Logic and draw code in `logic/calib.hpp`, wiring in `main.cpp`. Calibration chimes are reported in `Wizard::cue` for the caller to play (see the buzzer section). Deviations from Rust: the complete screen says "EEPROM updated OK" instead of "Flash updated OK". Not tested on hardware.

Radio setup (main menu item 7): 16 rows as in the Rust `setup.rs`. Throttle trim (OFF/IDLE/LINEAR), beeper, tones, backlight timer, backlight level (10%..100%, applied to the LCD at once), contrast (20..50, applied at once), battery warning (4.0..5.0 V), USB mode, PC13 power polarity, external switches, P7 analog, stick mode (MODE 1..4), gimbal type, PPM out and trainer in bits. The Input Setup row opens the Input Modes screen for SA..VRF (6 rows, or 10 with P7 analog) with DEFAULT..INST-TRIM. Each change saves the radio config at once, as in Rust. The menu returns `Action::SaveRadioConfig`, and `main.cpp` saves and applies the LCD settings. The stored LCD values are also applied at boot. Logic in `logic/menu.hpp`, host-tested in `radio_setup_test()`. Not tested on hardware.

Radio setup deviations: the hardware hooks of the Rust `hw/mod.rs` and `buzzer` are not ported. The values are stored, but PC13 module power, external switches and ADC do not change any pins, the remaining buzzer cues are not wired (see the buzzer section), the backlight timeout does not dim the screen, and USB mode does not re-init USB.

AFHDS 2A protocol (pure logic, host-tested): `logic/afhds2a.hpp` (constexpr, no heap, no virtual functions). It covers the 16-channel hopping table from the TX UID, the 38-byte stick packet (14 channels as 12-bit slots plus the 4 extended channels in the upper nibbles), the settings packet (50..400 Hz clamp, PWM/PPM, i-BUS/S.BUS), the failsafe packet (throttle to 988 µs, other channels hold), the four bind steps and the bind confirmation, RX ID capture and TX ID filtering, the downlink requests (settings and failsafe), telemetry sensors (voltage, temperature, RPM, vario, altitude, LQI), and the RSSI formula from the raw A7105 value. Host-tested in `afhds2a_test()`, with the Rust test cases as reference. Not tested on hardware.

A7105 driver and radio state machine (`logic/a7105.hpp` and `logic/afhds2a_radio.hpp`, pure logic, host-tested in `a7105_radio_test()`): register constants, the 50-byte init table (checked against Rust `a7105.rs`), power index mapping, CRC check, the 3.85 ms hop and bind sequence, the heartbeat gate, failsafe at packet 1569, the 53-tick loss timeout, and RX ID capture. Hardware glue in `hw/a7105.hpp` (SPI1 on PE12–PE15, reset, init, front-end and antenna switching) and `hw/rf.hpp` (TIM16 and GIO2/EXTI2_3 ISR bodies, called from `isr.cpp`). Not tested on hardware.

AFHDS 2A deviations: the Rust triple buffer is replaced by ISR-safe shared state under `CriticalSection`. `main.cpp` derives the TX ID from the UID (XOR of the three words, as in Rust), applies the active model's RX ID, power and RX output settings on boot and model switch, silences the A7105 for CRSF models, starts binding on boot with BIND held or on a 1 s BIND hold on the dashboard (cancelled by BIND or CANCEL), and saves a newly bound RX ID once the model is not armed. Power and RX output changes take effect on the next save of the active model. The dashboard status bar shows the AFHDS2A state (BIND, R:NN RSSI, RF:OK or NO RF), the model page shows the link state, and page P5 shows RSSI, link, packet counters (TX and RX), RX and TX voltage, and the session minimum RSSI and RX voltage (tracked from the first connected sample, as in Rust `status_bar.rs`).
 the physical DR switch while the editor is open does not select the switch yet (Rust `dr_change`).

Wing/mixer deviations: the pot and switch auto-select while moving a control (Rust `pot_change` and `sw_change`) is not ported. Rust returns to the wrong row from a mix line when Diff is shown; the port returns to the mix row it came from.

Vario (pure logic, host-tested in `vario_test()`): `logic/vario.hpp` ports Rust `vario.rs`. It covers the vertical speed filter from native telemetry (3:1 EMA) or from altitude changes (dt ≥ 80 ms, decay after 500 ms), the disconnect reset, the activation switch and motor lockout above 1100 µs, the climb and sink deadbands, the climb pitch and cadence, and the sink modes (Mute, Pulse, Continuous). The vario tone is planned through `logic/buzzer.hpp` (see the buzzer section). Not wired yet: the VarioSetup menu is not ported. Not tested on hardware.

Buzzer (pure logic, host-tested in `buzzer_test()`): `logic/buzzer.hpp` ports the tone presets of Rust `buzzer.rs` in Simple and Rich styles (`pattern_for`, with `Cue` covering the calibration chimes, trim, battery and RSSI alarms, critical and preflight warnings, inactivity, arm and disarm, and timer cues), the trim pitch (`trim_note`), the foreground and vario `Player`, the battery alarm (`BatteryWarnTimer`, low below the stored threshold, every 8 s), the RSSI alarm (`rssi_alarm`, `RssiWarnTimer`: below 40 is low, below 20 is critical), the inactivity and preflight timers, and the arm chime decision (`arm_cue`, switches 1..=22, silent while a menu is open). `hw/buzzer.hpp` drives PA8 as TIM1 CH1 (AF2) at 1 MHz ticks with CMSIS registers only. `Wizard::cue` in `logic/calib.hpp` reports the calibration chimes. Deviations from Rust: a zero pause advances at once (Rust would stall), the trailing pause after the last tone is skipped, tones below 100 Hz are silent, a disabled buzzer ignores `play`, and the Rust 33 ms frame step is replaced by the caller's `dt`. Wired in `main.cpp`: `hw::buzzer::init()` at boot, `Player::tick` every loop, `set_enabled` from `radio.audio_enabled` (applied each loop, so it follows the setup toggle), the PWM output synced at the end of each loop, the arm chime (`arm_cue`, `prev_armed` resynced on model switch), the calibration chimes (`Wizard::cue` after start and update), and the battery and RSSI alarms (RSSI only for AFHDS 2A). The alarms step only while the dashboard is shown, as in Rust. Not wired yet: the welcome chime, click, page and menu sounds, preflight and inactivity warnings, and the vario tone. The trim cues (step, centre and limit) and the instant-trim cue are wired from the trim controller. Not tested on hardware. Pin PA8 and TIM1 AF2 come from the Rust source comments and were not checked against the board schematic.Telemetry (pure logic, host-tested in `telemetry_test()`): `logic/telemetry.hpp` ports the value logic of Rust `ui/dashboard/pages/telemetry.rs`. It covers sensor freshness (`check_sensor_status`: 2.5 s timeout and disconnect, wrap-safe), the RF rate names (`rf_mode_name`), and the text and stale `*` mark of the 22 sensor tiles (`sensor_tile`) for both AFHDS2A and CRSF sources. `format_fixed` is in `logic/format.hpp` (Rust `format_fixed`). Dashboard `sensor_fresh` uses the same freshness check. Not yet ported: slot-to-tile storage (custom telemetry slots) and drawing of the tiles. The CRSF branch of page P5 is ported as `crsf_diag` (see the CRSF link diagnostics paragraph below). Deviations from Rust: for CRSF, tile 12 (VSPD) uses the CRSF vertical speed and tile 13 (ALT) uses the CRSF barometric altitude, while Rust uses the AFHDS2A fields in both cases. Not tested on hardware.

CRSF link diagnostics (pure logic, host-tested in `crsf_diag_test()`): `crsf_diag` in `logic/telemetry.hpp` ports the CRSF branch of Rust `draw_telemetry_page`. It builds the LQ, RSSI, SNR, antenna, TX power, rate, battery label (`nS:` for 2..9 cells, else `BAT:`), RX battery and capacity text, with the label prefixes, placeholders and stale `*` as in Rust. Page P5 shows it when the RF protocol is CRSF (`draw_crsf_telemetry_page` in `logic/dashboard.hpp`) and the AFHDS2A counters otherwise. `main.cpp` passes `hw::crsf::telemetry()` in the dashboard view. Deviations from Rust: none in the P5 layout; the footer reads "CRSF LINK DIAG" and ignores the bind state, as in Rust. Not tested on hardware.

Trim (pure logic, host-tested in `trim_controller_test()`): `logic/trim.hpp` ports the trim key state machine of Rust `trim.rs`. Keys 0..7 are the trim rockers (Roll, Pitch, Throttle, Yaw, each + and -), with one step per press, auto-repeat after 350 ms held and every 90 ms after that, the DFU lockout (Roll L and Yaw R), the ±25 step limit, the throttle lock until the radio setup enables throttle trim, and the 1.5 s active display of the last changed trim. `Controller::update` returns one `Event` (step, centre or limit) for the buzzer. The P1 dashboard footer shows `TRM A:+05`-style text for the active trim (`format_trim`), otherwise `P1/5`. `main.cpp` loads the trims from the active model on boot and model switch, enables throttle trim from `radio.throttle_trim` on boot and setup save, and steps the trims only while no menu or calibration is open, as in Rust. Trim auto-save (`AutoSave`, Rust `main.rs` section 8): a trim change restarts a 2000 ms cooldown, and when it runs out while disarmed the trims are written to the active model's EEPROM slot with `save_active_model`. A failed write is retried on the next loop, as in Rust. Trims are also saved on model switch. Instant trim (pure logic, host-tested in `instant_trim_test()`, Rust `main.rs` section 7): `Controller::instant_trim` adds the rounded roll, pitch and yaw stick deflections (40 counts per step, clamped to ±25) when any is non-zero, and shows the footer for the first changed axis (roll, then pitch, then yaw). When the sticks are centred and any trim is set, it resets roll, pitch and yaw to zero. Throttle is never changed. `instant_switch_down` reads the aux channels set to `AdcInputMode::InstantTrim` (the first 10 with the external ADC, 6 without) at raw ≥ 2048, and `InstantEdge` fires once per press on the rising edge, tracked even while a menu is open. The adjust uses `Cue::InstantTrim` (2400 Hz, two repeats in both styles, as the Rust raw tone), and the reset uses `Cue::TrimCenter`. The changed trims go through the same `AutoSave`. Deviations from Rust: the board-level instant-trim click is omitted, because Rust's `instant_trim_clicked` is always false on this board, and the dashboard shows no separate instant-trim text, as in Rust. Not tested on hardware.

Flight timer (pure logic, host-tested in `flight_timer_test()`): `logic/flight_timer.hpp` ports the timer engine of Rust `main.rs` section 8c. It resets on model change and on arming (switches 1..=22), counts down the model limit while `mixer::is_timer_active` is true, and counts up after expiry or when there is no limit. The countdown, minute and elapsed cues and a 2400 Hz reset tone are returned as `buzzer::Cue`. Holding CANCEL for 1 s on the dashboard resets the timer, shows the "TIMER RESET!" toast for 800 ms, and starts a 1.5 s cooldown with a release guard. The hold progress bar appears after 80 ms (`flight_timer::modal`, drawn by `dashboard.hpp`). The P1 footer shows the time as `MM:SS` (`format_timer`, `+` once expired, blinking inverted), after the trim footer and only when the timer source is not off. Settings come from the active model (`timer_secs`, `timer_source`, `arm_switch`). Runtime state is not stored, as in Rust. Deviations from Rust: the manual reset-click input is omitted, because Rust's `timer_reset_clicked` is always false on this board. Not tested on hardware.

Bind (pure logic, host-tested in `bind_test()`): `logic/bind.hpp` ports the BIND key of Rust `main.rs` section 5 for AFHDS 2A. Holding BIND for 1 s on the dashboard starts binding once per hold (`Controller`, not repeated while held). While binding, a BIND press or CANCEL stops it with a click. A hold is ignored while a menu or calibration is open, and the hold resets. Binding is shown only when the link is AFHDS 2A (`binding_shown`, as in Rust `!is_crsf && rf::is_binding()`). On every dashboard page, the "[ESC] Finish Bind" footer replaces the page footer while binding, and it takes precedence over the trim and flight timer footers (`footer_kind`: bind > trim > timer > default, as in Rust `gimbals::render_footer`). `main.cpp` drives `hw::rf::set_bind_mode` from the controller. Deviations from Rust: the 2400 Hz / 150 ms start tone is not played, and a short BIND tap that cycles to the next page is not ported. Not tested on hardware.

Model setup copy (pure logic, host-tested in `model_copy_test()`): `logic/model_copy.hpp` ports the Copy row of the model setup screen (row 5, Rust `screens/model.rs`). OK on the row opens a destination picker that starts on the slot after the active model and wraps over all 20 slots. UP and DOWN move it, OK copies the active model to the chosen slot through `storage::save_model_to_slot`, and ESC cancels with no write. While choosing, the row reads `Copy -> M01`-style (1-based) and the footer shows `[OK] Duplicate [ESC] Cancel`. The strong types `SrcSlot` and `DstSlot` keep the source and destination apart. The menu returns `Action::CopyActiveModel` with the destination, and `main.cpp` performs the write. The model setup screen now scrolls over 7 rows. Deviations from Rust: the active model stays in place, since only the active slot is held in memory, so the source must be the active slot (`copy_model` returns false otherwise); no menu tone is played, because menu sounds are not wired. Not tested on hardware.

Protocol and reset (pure logic, host-tested in `protocol_reset_test()`): `logic/protocol.hpp` holds the RF protocol enum (AFHDS2A or CRSF, stored as `ModelConfig::rf_protocol`), its labels, the hardware link each protocol needs (CRSF UART on and A7105 muted only for CRSF), and the factory reset of a model slot. The model setup screen has a Protocol row (row 6, Rust `screens/model.rs` row 8) that opens the PROTOCOL SETUP sub-screen, with the same toggle as Rust `setup.rs`: OK starts editing, UP and DOWN switch the protocol, and a second OK saves the active model. ESC while editing keeps the toggled value in RAM without saving, as in Rust, and ESC again returns to Model Setup. A Reset row (row 7, `Reset: [OK Defaults]`) replaces the active model with the factory defaults of its slot (`storage::default_model_config`) and saves it, as Rust `ModelConfig::default_for_index`. `main.cpp` applies the link on boot, on model switch, after a reset, and whenever the protocol changes in RAM (`apply_protocol_link`). Deviations from Rust: the PROTOCOL SETUP screen has only the Proto row (the AFHDS2A bind, power, servo rate, RX output, CRSF baud, duplex, arm mode and configurator rows are not ported here); the reset reloads the trims from the reset model, which Rust does not do, so the old trims are not written back; the bound RX ID is cleared with the rest of the model, as in Rust, and the RF is re-applied at once; there is no confirm step, because Rust has none; no system or radio factory reset exists in Rust, so none is added; the CRSF UART is now disabled for AFHDS2A models (it used to be enabled at boot for every model). Not tested on hardware.

Trainer (pure logic, host-tested in `trainer_test()`, hardware in `hw/trainer.hpp`): `logic/trainer.hpp` ports Rust `trainer/ppm_in.rs`, `ppm_out.rs` and `handover.rs`. The PPM decoder takes pulses from the TIM15 input capture on PF9 (falling edge), syncs on gaps of 3 to 30 ms, keeps 8 channels clamped to 988..2012 µs, aborts a frame on an out-of-range pulse, and drops the signal after 100 ms without a frame. The PPM generator builds the 22.5 ms frame on PF10 from the 8 output channels (clamped to 900..2100 µs, 400 µs sync). The handover replaces channels 1..4 with the student's trainer input while the SD switch is down, and falls back to the instructor when the student signal is lost or the instructor's sticks are deflected (roll, pitch or yaw beyond ±50 µs, or throttle above 1050 µs). `main.cpp` enables the input and output from the radio setup (`trainer_in`, `trainer_out`), applies them at boot and on save, and runs the handover before the RF publish. The Rust `set_ppm_*` calls become a single apply on `SaveRadioConfig`. Not tested on hardware.

Trainer deviations: USB sim mode is not ported (the sim-mode check is always false), the generator re-arms its compare to the counter plus 400 µs when enabled so a stale compare cannot stall the frame, the timer counter is restarted only when the timer is stopped, the decoder is reset on enable, CC2 is not an AF output (PF10 is driven by GPIO from the ISR, as in Rust), the trainer state on the dashboard are not ported. Pins PF9 and PF10 and the TIM15 use come from the Rust source and were not checked against the board schematic.

Not yet ported: USB, arm chimes, custom telemetry slots.




## Build

Firmware (clang + arm-none-eabi-gcc 13 newlib for Cortex-M0):

    cmake -S . -B build-fw -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi-clang.cmake -DCMAKE_BUILD_TYPE=MinSizeRel
    cmake --build build-fw

Host tests (clang with C++26 support, e.g. LLVM 20 or newer):

    cmake -S . -B build-host -DCMAKE_CXX_COMPILER=clang++
    cmake --build build-host
    ./build-host/host_logic_tests

## Layout

- `src/ferrox/arch/`: CMSIS include, critical section
- `src/ferrox/chip/`: clock, reset, DFU, watchdog
- `src/ferrox/hw/`: GPIO, ADC, UART, keys, CRSF link
- `src/ferrox/time/`: SysTick millis
- `src/ferrox/logic/`, `src/ferrox/util/`: pure logic and ring buffer (host-testable)
- `third_party/cmsis/`: ARM CMSIS_5 core and ST CMSIS device files (Apache-2.0)

## Notes

- Target is single-core Cortex-M0 (ARMv6-M). `std::atomic` acquire/release and read-modify-write lower to libatomic calls there, so shared ISR state uses `volatile` plus compiler fences.
- Not verified on hardware yet.
